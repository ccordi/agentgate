## Local-LLM Guard Evaluation

> Frozen snapshot (measured 2026-06; see `eval/redteam/llm_eval.py` and
> `extra_probes_eval.py` — results JSON under `eval/redteam/runs/`). Not regenerated by
> the report command.

A Q4-quantized **Gemma 4 26B A4B IT**, served locally through oMLX, is the primary guard evaluated here. The comparison uses a Q4-quantized **Qwen3.6-35B-A3B** and the DeBERTa baseline. The LLM guard is opt-in (`AGENTGATE_GUARD_BACKEND=llm`); `deberta` remains the code default. Deployments must set both `AGENTGATE_JUDGE_MODEL` and a loopback `AGENTGATE_JUDGE_BASE_URL`, because the guard is not allowed to send untrusted content to a cloud endpoint. The LLM guard receives each tool output as one prompt. On the short, single-window `latentinjection` probes used here, its higher recall reflects better handling of indirect framing, not access to text outside DeBERTa's window. It produced no false positives in the 109 scanned tool-output samples.

| Metric / Sub-Corpus | Gemma Guard (Primary) | Qwen Guard (Alternative) | DeBERTa Baseline | Note / Context |
| --- | --- | --- | --- | --- |
| **Recall — Independent Garak** | **98.6% (71/72)** | 88.9% (64/72) | 30.6% (22/72) | NVIDIA garak `latentinjection` (independent) |
| **Recall — seed_mutate** | 100.0% (28/28) | 100.0% (28/28) | 32.1% (9/28) | ⚠️ **Circular** (discounted; Gemma/Qwen family bias) |
| **FP — Untrusted channel** (scanned) | **0.0% (0/109)** | 0.0% (0/109) | 11.0% (12/109) | Benign `tool_output` captures — what the guard *does* scan |
| **FP — User channel** (not scanned *by the LLM guard*) | 15.9% (7/44) † | 4.5% (2/44) | 11.4% (5/44) | Benign `user` captures — what the LLM guard's channel-scoping skips, and what DeBERTa still reads |
| **FP — Combined** | 4.6% (7/153) | 1.3% (2/153) | 11.1% (17/153) | All organic benign captures (FP) |

† Format-sensitive — measured on user turns as the agent emits them, with a timestamp prefix.
The committed corpus ships those turns stripped, where the same guard over-fires on
**52.3% (23/44)**. Both numbers are real; they are measurements of different text. See the
trust-boundary note and the reproduction table below. The tool-channel rows are unaffected.

> [!NOTE]
> **Result.** On garak `latentinjection`, the local-LLM guard caught more indirect-injection attacks than DeBERTa and flagged 0 of 109 benign tool-output samples. The seed_mutate result has model-family overlap between generation and guarding, so the garak result is the stronger recall evidence.
>
> **On the trust boundary.** The LLM backend scans tool/retrieved content and skips the user's own turn. On the deduplicated capture (44 rows; 29 distinct texts after removing timestamp prefixes), it flagged **15.9% (7/44)** of benign user messages when run as a check. Qwen flagged 4.5% (2/44). The sample is small, comes from one automated agent, and contains few imperative human commands. It is also format-sensitive: removing the agent's timestamp prefix — the anonymized form committed here — raised Gemma's result to **52.3% (23/44)**. These figures explain the backend's tool-only scope; they do not establish a stable user-channel false-positive rate. The heuristic and DeBERTa backends do scan the newest user turn, so this is not a gateway-wide rule.

### Robustness probes

Two predicted failure modes, probed on **bare** encoded payloads (no cleartext "decode this and follow it" lure) and on benign tool results that merely *quote* attack strings:

| Probe | Gemma Guard | DeBERTa | Combined (OR) | Finding |
| --- | --- | --- | --- | --- |
| **Obfuscation in tool channel** — bare base64 / ROT13 / zero-width, n=15 | **93.3% (14/15)** | 46.7% (7/15) | **100% (15/15)** | The LLM decodes most bare encoded payloads (rationales show in-context decode); misses one ROT13 |
| **Security-meta-content FP** — benign tool results discussing injection, n=15 | **0.0% (0/15)** | 40.0% (6/15) | 40.0% (6/15) | DeBERTa over-fires on benign text that *quotes* attack strings; the LLM reads context and does not |

> [!NOTE]
> **Why keep both layers.** Neither detector was perfect on bare obfuscation (LLM 93.3%, DeBERTa 46.7%), but their misses did not overlap in this run, so the OR-combination reached 100%. DeBERTa is also faster (~40 ms p50, with a longer tail under local-model load) and scans the user channel that the LLM backend skips.
> **Caveats:** n=15, single guard model (Gemma), single serving configuration — quantization, sampling settings and the server's own decode behavior all move an LLM guard's verdicts, so the same model served differently can score differently. Complementarity is suggestive, not proven at scale.

### Latency (deployment cost)

Gemma 4 26B A4B IT, served locally via oMLX: **warm p50 ≈ 1.38 s, p95 ≈ 1.62 s** per untrusted item; **cold VRAM-swap load ≈ 3.6 s** (first call after the model is evicted). The guard runs only when the request has trailing tool output, so ordinary user↔assistant turns do not pay this cost. Whether ~1.4 s is acceptable depends on the workload.
